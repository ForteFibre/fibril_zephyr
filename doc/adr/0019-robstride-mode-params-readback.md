# 0019. RobStride の設定をモードごとに書き、読み戻して確かめてから有効化する

## Status

Proposed

native_sim のテストとビルドだけを確かめていて、実機ではまだ確かめていない。

## Context

これまでのハンドシェイクは、停止と `run_mode`、上限、ゲイン、有効化、指令の段を 1 周期に 1 段ずつ進めていた。
段が済んだかどうかは、CAN コントローラが送信を受け付け、完了コールバックが失敗を報告しなかったことだけで決めていた。

これではモータが値を受け入れたことは分からない。
classic CAN の ACK はバス上のどのノードでも返せるので、同じバスに別のモータがいれば、宛先が取りこぼしたフレームも「線路に出た」と報告される。
有効化についても同じで、有効化フレームを送ったあと Running になったかを見ずに指令を送り始めていた。
一度も Running にならなかったモータには有効化を送り直さず、指令だけを送り続けていた。

`robstride_actuator_bridge_ros2` の `feature/wait_parameter_apply` は、この 2 つを次のように解いている。

- パラメータを 1 つ書くたびに GET_PARAM で読み戻し、許容誤差に入るまで最大 3 回書き直す。
- 有効化のあと、Running で error_code が 0 の feedback が来るまで指令を送らない。
- どちらかが失敗したら、200 ms おいてから停止フレームからやり直す。
- 書くパラメータはモードごとに決まっていて、PP の `vel_max` と `acc_set`、速度モードの `acc_rad` のように、モード固有のものも書く。

[ADR 0006](0006-robstride-fcan-node-parity.md) は「ゲインはモード別に持てない」とし、1 組で足りるかを実機で確かめるのを先にした。
しかし ROS 2 実装と同じ値を同じ名前で持てないと、PC から基板へ移したときに調整し直しになる。
この ADR は 0006 のその項を置き換える。

## Decision

### 1. 期待値はモータごとの構造体に持ち、書く値と比べる値を同じところから取る

`struct robstride_mode_params`（`max_velocity`、`acceleration`、5 つのループゲイン）をモードごとに 1 つ、モータごとに持つ。
`robstride_set_mode_params()` で渡し、`robstride_set_gains()` は廃止する。

ハンドシェイクが書くパラメータは、ドライバの中の「スロット」の並びで表す。
スロットごとにインデックスと許容誤差を固定し、値は書くときも比べるときも、その時点の `mode_params`、`limits`、`mode` から取り出す。
書いてから応答が来るまでのあいだにアプリケーションが値を変えれば、応答は食い違い、新しい値で書き直される。

モードごとに書くものは ROS 2 実装と同じにする。

| モード | 書くもの |
| --- | --- |
| 全モード | `run_mode`、`limit_cur`、`limit_spd`、`limit_torque` |
| PP | `vel_max`、`acc_set`、`loc_kp`、`spd_kp`、`spd_ki`、`cur_kp`、`cur_ki` |
| CSP | `loc_kp`、`spd_kp`、`spd_ki`、`cur_kp`、`cur_ki`。`limit_spd` には `max_velocity` を入れる |
| 速度 | `acc_rad`、`spd_kp`、`spd_ki`、`cur_kp`、`cur_ki` |
| 電流、運転制御 | `cur_kp`、`cur_ki` |

CSP の `limit_spd` は `max_velocity` と上限の小さいほうにする。
ROS 2 実装は `max_vel` で上書きするが、devicetree の `max-velocity-mrad-s` を超えられると、機械に合わせて決めた上限の意味がなくなる。

値を渡されていないモードでは、今と同じくモード固有のものを書かず、モータ自身のメモリの値で動かす。
ブロック型は起動時に全モード分を渡すので、ブロック型から見た動きは ROS 2 実装と同じになる。

### 2. 書く、読む、確かめるを周期に分けて進める

送信ワークはシステムワークキューで動くので、応答を待ってブロックできない。
そこで各モータの状態を 2 つのマスクで持つ。

- `param_to_write`：まだ書いていないスロット
- `param_to_verify`：書いたが、まだ一致を確かめていないスロット

どちらにも無いスロットは、モータが値を持っている。

1 周期に 1 段ずつ、次の順に進める。

1. `run_mode` は停止フレームと一緒に、単独で書く。
2. ほかのスロットは、最大 5 つずつ書く。
3. 次の周期に、書いた分の GET_PARAM を送る。
4. 受信側は、応答の値が期待値と許容誤差の中で一致すれば、そのスロットを `param_to_verify` から外す。
5. `CONFIG_MOTOR_ROBSTRIDE_VERIFY_TIMEOUT_MS`（20 ms）たっても残っていれば書き直す。
6. `CONFIG_MOTOR_ROBSTRIDE_VERIFY_RETRIES`（3 回）続けて確かめられなければ失敗とする。

書き込みと読み出しは同じ周期に積まない。
コントローラは ID の小さいフレームを先に送るので、同じ周期に積むと GET_PARAM（種別 0x11）が、確かめたい SET_PARAM（0x12）より先に線路へ出て、古い値を読みうる。
同じ理由で、目標値の書き込みと有効化（0x03）も別の周期にする。

一致しない応答が来ても、すぐには書き直さない。
応答にはインデックスしか無く、前の読み出しへの遅れた応答と見分けられないからで、期限まで正しい応答を待つ。

許容誤差は ROS 2 実装と同じにする（1e-3、`spd_ki`、`cur_kp`、`cur_ki` は 1e-4。`run_mode` は完全一致）。
ビット列で完全に一致することを求めると、モータが内部で丸めて返したときに一度も有効化されなくなる。
その危険のほうが、1e-3 の差を見逃す危険より大きい。

### 3. Running を確かめてから指令を送る

全スロットを確かめたら、目標値（`loc_ref`、`spd_ref`、`iq_ref`）を書き、次の周期に有効化する。
目標値を先に書くのは、モータが前に持っていた目標へ動き出さないようにするためで、ROS 2 実装と同じである。
運転制御には目標値のパラメータが無いので、この段を飛ばす。

有効化のあと、Running で error_code が 0 の feedback が来るまで指令を送らない。
`CONFIG_MOTOR_ROBSTRIDE_RUNNING_TIMEOUT_MS`（100 ms）のうちに来なければ失敗とする。
ただし、キャリブレーション中のモータは待ち続ける。

### 4. 失敗したら間をおいて停止からやり直す

読み戻しの失敗でも、Running にならない失敗でも、`CONFIG_MOTOR_ROBSTRIDE_CONFIGURE_BACKOFF_MS`（200 ms）おいてから、停止と `run_mode` からやり直す。
失敗した段だけをやり直さないのは、値を受け付けないモータや Running にならないモータは、こちらの知らないうちにリセットしているかもしれないからである。
`motor_enable()` が呼ばれたときは待ちを解く。明示の有効化は、すぐ再挑戦してほしいという要求だからである。

### 5. 完了コールバックの失敗より、読み戻しを信じる

これまでは、完了コールバックが失敗を報告した段を、無条件にやり直していた。
今回からは、書き込みのフレームはスロットごとの文脈を持つ。
そのスロットがすでに読み戻しで確かめられていれば、失敗の報告は前の書き込みのものなので無視する。
まだ確かめていなければ、読み戻しの期限を待たずにすぐ書き直す。

読み戻しを切った構成（`CONFIG_MOTOR_ROBSTRIDE_VERIFY=n`）では、完了コールバックの失敗しか手がかりが無いので、今と同じくやり直す。

### 6. 動いている途中で値を変えたときは、止めずにそのスロットだけ書き直す

いまのモードの値を `robstride_set_mode_params()` や `robstride_set_limits()` で変えたら、そのスロットを `param_to_write` に戻す。
停止もせず、有効化もやり直さない。
書いて確かめるあいだの 2〜4 周期だけ、指令が止まる。

## Consequences

- 有効化してから最初の指令までが、約 20 ms から約 45 ms に延びる（PP で 9 周期）。
- 読み戻しの分だけバスの負荷が増える。ただし増えるのはハンドシェイクのあいだだけで、指令の周期は変わらない。
- 答えないモータ（電源が入っていないモータなど）は、約 0.3 秒ごとに設定をやり直す。警告のログは、失敗が始まったときに 1 回だけ出す。
- `struct robstride_feedback` に `configured` と `configure_failures` を足した。ブロック型は `is_ready` に `configured` を加え、`diagnostics` に両方を出す。
- `RobstrideMotor` の param から `gains/*` を外し、ROS 2 実装と同じ名前で `motion/`、`position/`、`trajectory/`、`velocity/`、`current/` を足した。param のビットの並びが変わるので、`gains/*` を使っていた launch とパラメータファイルは書き直す。
- 許容誤差と、停止中のモータが GET_PARAM に答えるかは、実機で確かめていない。
