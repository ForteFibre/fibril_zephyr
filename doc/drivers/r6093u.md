# R6093U（`cruizcore,r6093u`）

CruizCore R6093U は、姿勢（roll、pitch、yaw）、角速度、加速度を UART で送り続けるジャイロである。
このドライバはそれを受け、IMU クラスの device として見せる。
PCMainFW（Main 2024 V1 の Mbed ファームウェア）の `lib/R6093U` にあたる。

共通の IMU インタフェースは [include/drivers/imu.h](../../include/drivers/imu.h) にある。
このドライバ固有の診断は無いので、専用のヘッダは持たない。
IMU クラスを足した理由と却下した案は [ADR 0020](../adr/0020-imu-driver-class.md) にある。

## デバイスの構成

ノードは、つながっている UART の子に置く。
UART は 38400 bps にする（R6093U の速度は固定である）。

```devicetree
&uart5 {
        current-speed = <38400>;
        status = "okay";

        gyro: r6093u {
                compatible = "cruizcore,r6093u";
        };
};
```

ドライバは割り込み駆動の UART API（`CONFIG_UART_INTERRUPT_DRIVEN`）で受ける。
38400 bps では 1 秒に約 3800 バイトしか来ないので、DMA は使わない。
`CONFIG_IMU_R6093U` はこのノードがあると既定で立ち、`CONFIG_UART_INTERRUPT_DRIVEN` を select する。

| プロパティ | 既定 | 意味 |
| --- | --- | --- |
| `stale-timeout-ms` | 50 | 最後のパケットからこれより経つと `stale`。10 ms ごとのパケットを 4 つ落とすまでは鮮度を保つ |
| `offline-timeout-ms` | 500 | これより経つと offline。受信を張り直す間隔も兼ねる |

## パケット

R6093U は約 100 Hz で、要求されなくても 26 バイトのパケットを送る。
並びは PCMainFW のドライバから読んだもので、データシートとは照らし合わせていない。

| バイト | 中身 |
| --- | --- |
| 0、1 | ヘッダ `0xA6 0xA6` |
| 2 | 使っていない（連番と思われる） |
| 3〜8 | roll、pitch、yaw（int16、0.01 deg） |
| 9〜14 | 角速度 x、y、z（int16、0.01 deg/s） |
| 15〜20 | 加速度 x、y、z（int16、1 mg） |
| 21〜24 | 使っていない |
| 25 | 2〜24 バイト目の和の下位 8 bit |

int16 はどれも little endian である（PCMainFW のコメントは big endian と書いているが、処理は little endian）。

ドライバは先頭の 2 バイトがヘッダでなければ 1 バイトずつずらし、checksum が合わなければ、次のヘッダの組の位置まで捨てる。
パケットがどこで切れて届いても、壊れたパケットのすぐ後に次が続いても、次の正しいパケットから読める。

## 値の意味

| フィールド | 中身 |
| --- | --- |
| `accel` | 加速度（m/s²）。1 mg を 9.80665 / 1000 m/s² として換算する。重力を含む |
| `gyro` | 角速度（rad/s） |
| `roll`、`pitch` | デバイスが返した角度（rad） |
| `yaw` | 折り返さない yaw（rad）。下の「yaw の連続化」 |
| `yaw_epoch` | yaw の連続化をやり直すたびに進む |
| `timestamp_ms` | 最後に正しいパケットを受けた時刻 |
| `error_count` | checksum の合わないパケットと、UART のエラー（overrun、framing など）の数 |

軸と符号はデバイスのままである。
**R6093U の yaw は、機体の yaw と向きが逆になる**（fibril_localization の `basic_deadreckoning` は `-yaw` で使う）。
符号を直すのは消費者である。

## yaw の連続化

デバイスの yaw は ±180° で折り返す。
ドライバは、前のパケットとの差を ±180° の範囲に直して足していく。
足すのは 0.01 deg の整数のままで、float に直すのは読み出すときだけなので、何回転しても丸めの誤差は溜まらない。

パケットは 10 ms ごとに来て、角速度は ±250 deg/s で頭打ちになる。
1 つの間に回れるのは 2.5° なので、近い方の向きを選べば取り違えない。
数百 ms 途絶えた後の最初のパケットでも、連続化はやり直さない。
その間に半回転以上回っていれば、1 回転ずれる。

連続化を始め直すのは、最初のパケットと、`imu_reset()` の後の最初のパケットである。
このとき `yaw_epoch` が進む。

## リセット

`imu_reset()` は `$MIB,RESET*87` を送る。
R6093U はリセットし、yaw を 0 に戻す。
ドライバは連続化を次のパケットから始め直す。
コマンドは、PCMainFW と同じく末尾の NUL まで送る（NUL が要るかは、データシートが無く確かめていない）。

**起動時にも 1 回送る。**
PCMainFW と同じく、イメージが起動したときの向きが yaw の 0 になる。

## 鮮度と、受信が止まったとき

| 最後のパケットから | `imu_get_feedback()` | `online` | `stale` |
| --- | --- | --- | --- |
| まだ 1 つも無い | `-ENODATA`（中身は書かない） | — | — |
| `stale-timeout-ms` 以下 | 0 | true | false |
| `offline-timeout-ms` 以下 | `-EAGAIN` | true | true |
| それより長い | `-EIO` | false | true |

`-EAGAIN` と `-EIO` のときも、最後の値は書き込む。
判定は読み出したときの時刻で行う。

2020 年に、別の基板の R6093U のドライバで、受信が数分から 10 分ほどで止まった（fibril の wiki の r6093u のページ）。
UART のエラーフラグを読むと受信が戻ったので、overrun が立ったまま受信が止まったものと考えられる。
このドライバは、それを 2 段で防ぐ。

- 受信の割り込みのたびに `uart_err_check()` を呼び、エラーを数えてクリアする。そのときに組み立て中だったパケットは捨てる。
- 何も届かないまま `offline-timeout-ms` が過ぎると、watchdog が受信の割り込みを止め、エラーをクリアしてから、また有効にする。止まっている間は `offline-timeout-ms` ごとに繰り返す。

## テスト

- [tests/drivers/imu/r6093u](../../tests/drivers/imu/r6093u/src/main.c) — 起動時のリセット、SI 単位への換算、±180° をまたぐ yaw の連続化（両向き、複数回転）、リセットと `yaw_epoch`、checksum の誤りと UART のエラーを数えて捨てること、ゴミや分割されたパケットからの同期、stale と offline、止まった受信を watchdog が張り直すこと

`uart_emul` が UART を模擬するので、`native_sim` で完結する。

```shell
west twister -T tests/drivers/imu/r6093u --integration
```

## 実機で確かめていないこと

2026-10-26 時点。

- パケットの並び、単位、リセットのコマンドを、データシートと照らし合わせていない。
- STM32 の UART で、10 分を超えて受信が止まらないこと。
