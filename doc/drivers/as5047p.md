# AS5047P 磁気角度センサ（`ams,as5047p`）

ams AS5047P（14 bit のオンアクシス磁気角度センサ）を SPI で読み、encoder クラスの device として見せるドライバ。
1 回転の中の絶対角度を、折り返しを解いた積算位置にする。

共通のエンコーダインタフェースは [include/drivers/encoder.h](../../include/drivers/encoder.h) にある。
失敗の原因の内訳、磁場の状態、ゼロ点のレジスタは、機種専用のヘッダ [include/drivers/encoder/as5047p.h](../../include/drivers/encoder/as5047p.h) にある。

## デバイスの構成

ノードは SPI コントローラの子に置く。

```devicetree
&spi1 {
        cs-gpios = <&gpioa 4 GPIO_ACTIVE_LOW>;

        angle0: as5047p@0 {
                compatible = "ams,as5047p";
                reg = <0>;
                spi-max-frequency = <8000000>;
        };
};
```

SPI はモード 1（CPOL=0、CPHA=1）、MSB が先である。
`spi-max-frequency` は 10 MHz まで書ける（デバイスの上限）。
16 bit のフレームを 8 bit の 2 語として送るので、16 bit の語を扱えないコントローラでも動く。
フレームごとに CS を上げ下げする。デバイスは CS の立ち上がりでコマンドを取り込むので、2 フレームを 1 回の CS で送ると 1 つの壊れたフレームとして読まれる。

`invert-direction` を付けると、位置と速度の符号が逆になる。
`single_turn` はデバイスが返した値のまま変わらない。
デバイスの DIR 設定には触らない。

`CONFIG_ENCODER_AS5047P` は、このノードがあれば既定で立つ。

## ポーリング

ドライバは読み出し要求のあるなしに関わらず、`poll-interval-us`（既定 1000）ごとに ANGLECOM を読む。
角度は 1 回転で折り返すので、1 回転に 2 回以上読まないと積算を復元できないためである。
1 回の読み出しの間の回転が半回転未満でなければならず、既定の 1 ms では 30000 rpm にあたる。

読み出しは device ごとのスレッドで行う（`CONFIG_ENCODER_AS5047P_THREAD_PRIORITY`、`CONFIG_ENCODER_AS5047P_THREAD_STACK_SIZE`）。
直交エンコーダ（[qdec_stm32](qdec_stm32.md)）のように `k_timer` の満了ハンドラで読まないのは、SPI の転送が待ちを伴い、割り込みの文脈では呼べないためである。
読み出しが周期を超えたときは、過ぎた境界を捨てて次の境界まで待つ。

1 回の読み出しは 2 フレームかかる。
デバイスはコマンドへの応答を次のフレームで返すので、読み出しのコマンドの後に NOP を送る。
`poll-interval-us` がカーネルの 1 tick より短いと、tick に切り上げられる。

## 値の意味

| フィールド | 中身 |
| --- | --- |
| `position` | 角度の差分を積算した値。16384 counts/rev（センサの軸 1 回転）。`encoder_set_position()` のオフセットを含む |
| `velocity` | 直前の読み出しとの差分を、実際に測った間隔で割った値（counts/s） |
| `sample_interval_us` | その間隔 |
| `single_turn` | デバイスが返した ANGLECOM（0〜16383）。デバイスのゼロ位置を引いた後の値 |
| `position_epoch` | 積算をやり直すたびに進む |
| `online` | `offline-threshold` 回続けて読めなかったら false |
| `stale` | 直前の読み出しが失敗したら true |
| `error_count` | 読めなかった回数の合計。原因ごとの内訳は `as5047p_get_stats()` |

`get_resolution` は 14（bit）を返す。

ANGLECOM は、デバイスが回転速度による遅れ（DAEC）を補償した角度である。

## 失敗の扱い

失敗は 3 つに分けて数える（`enum as5047p_error_cause`）。

| 原因 | 起きること | 考えられる原因 |
| --- | --- | --- |
| `AS5047P_ERROR_SPI` | SPI コントローラが転送をエラーで返した | コントローラの設定、DMA |
| `AS5047P_ERROR_PARITY` | 応答の偶数パリティが合わない | 配線のノイズ、クロックが速すぎる |
| `AS5047P_ERROR_FLAG` | 応答は正しく届いたが、デバイスがエラーフラグを立てた | デバイスが受け取ったフレームが壊れていた。原因は `last_errfl` |

エラーフラグを見たら、ドライバはすぐに ERRFL を読む。
ERRFL は読むとクリアされ、クリアするまでフラグはすべての応答に立ち続けるためである。
読んだ値は `as5047p_stats.last_errfl` に残る（`AS5047P_ERRFL_FRERR`、`AS5047P_ERRFL_INVCOMM`、`AS5047P_ERRFL_PARERR`）。

失敗した読み出しは、どれも位置を更新しない。
`offline-threshold`（既定 3）回より少なければ、最後に読めた値を `stale` として残す。
それ以上続いたら `online` を false にし、次に読めたときに積算をやり直す。
読めない間に軸が半回転以上回ったかどうかは分からないためである。

**磁場の状態は失敗として数えない。**
磁石が遠すぎても近すぎても、SPI の読み出しは正しく通る。
磁場を確かめるには `as5047p_read_diag()` で DIAAGC を読む（`magh`、`magl`、`cof`、`lf`、`agc`）。
この関数は自分で転送するので、制御ループから毎回呼ぶものではない。

## ゼロ点

デバイスは ZPOSM と ZPOSL のゼロ位置を角度から引いてから返す。
このレジスタは揮発性で、電源を入れ直すと OTP の値（書いていなければ 0）に戻る。
電源をまたいで保つには OTP に書くしかなく、書き直せないので、ドライバは書かない。

| 関数 | 振る舞い |
| --- | --- |
| `encoder_set_zero()` | 現在の角度がちょうど 0 になるようにゼロ位置を書く。電源を切ると消える |
| `as5047p_get_zero_position()` | 今のゼロ位置を読む（counts、0〜16383） |
| `as5047p_set_zero_position()` | ゼロ位置を書く。アプリが自分で保存したゼロ点を、起動後に戻すのに使う |

ZPOSL の上位 bit（磁場のエラーフラグを有効にする bit）は、ゼロ位置を書くときに残す。
ゼロ位置を変えると `single_turn` が跳ぶので、次の読み出しで積算をやり直し、`position_epoch` が進む。

## API の振る舞い

| 関数 | 振る舞い |
| --- | --- |
| `encoder_get_feedback()` | 一度も読めていなければ `-ENODATA`、`online` が false なら `-EIO`、`stale` なら `-EAGAIN` |
| `encoder_set_position()` | 現在の積算位置を指定の値にする。デバイスには何も書かない |
| `encoder_reset()` | 次の読み出しから積算をやり直す。それまでは `-ENODATA` になる。デバイスにはリセットのコマンドが無い |
| `encoder_set_zero()` | 上の「ゼロ点」 |

機種専用の関数は SPI の転送をするか、転送の間ポーリングのスレッドが持つ mutex を取るので、割り込みの文脈から呼べない。
